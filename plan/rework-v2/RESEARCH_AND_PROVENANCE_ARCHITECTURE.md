# Research and provenance architecture

Status: proposed binding implementation contracts, not implemented schema. Read with PRODUCT_MODEL invariants. Names below are implementation targets; migration numbers are deliberately unallocated.

## A. Durable identity and scope

**Research = Watch.id.** Watch already owns monitoring state, policy, approved vocabulary and source Monitors across Topic/Question targets. Topic lacks this lifecycle; ResearchQuestion would force every interest into a question. A new Research root would duplicate Watch. Retain existing target uniqueness and no new user-facing retarget operation in MVP. Existing Story merge/split/resolution can change target bindings or disable a conflicting Watch; preserve Watch IDs and capture those transitions in scope/lifecycle history (D20).

Add `watches.original_intent` (immutable initial prose), `current_scope_revision_id`, and `watch_scope_revisions`: id, watch_id, revision_number, intent, focus_areas_json (stable local IDs, names, descriptions), terms/inclusions/exclusions snapshot, actor, approved_at, origin, previous_revision_id, target_type and target_id snapshot. Unique(watch_id,revision_number). Initial intent backfill uses the persisted target description/question, labeled `legacy_current`, not claimed to be original when unknown. Existing target terms and `watch_vocabulary` remain matching inputs; the revision is their immutable approval snapshot, not a second independently editable vocabulary store. One transactional service updates target/vocabulary and creates Watch and Monitor scope snapshots. Legacy advanced edits of a Watch-bound target must go through this service or record a corresponding revision, never silently drift.

Do not require a one-to-one Watch revision reference on `monitor_scope_history`: identical semantic scope reuses its existing version. Old rows remain valid; observations pin both identities independently. Every new observation pins the Monitor scope version and Watch revision at admission. Scope edits affect future observations; no automatic historical reclassification. Focus-only edits can create a revision without changing matching semantics. Historical Briefings retain the revision used to create them.

## B. Historical membership and evidence admission

Keep `watch_sources` as the **current attachment projection** for compatibility. Add `watch_source_memberships`: id, watch_id, source_id, monitor_id, endpoint_id, approved_candidate_id, monitored_from, monitored_until nullable, approval_actor, acquisition_policy_snapshot, provenance_status. Explicit interval_state is open/closed/legacy_unknown; partial unique (watch_id,source_id) WHERE interval_state=open. Unknown end dates never imply active membership. Existing current links backfill an open interval from their recorded creation time, with `legacy_attachment` provenance. This table is authoritative for historical approval; current projection and interval are written atomically.

Detach closes the interval, disables this Monitor and deletes only the current projection, in one transaction. Reattach reuses the per-need Monitor and opens a new interval. Source and evidence are never deleted. Pause is distinct from detach: it disables future admission but does not close the Source approval interval. Watch lifecycle transitions need append-only status events (Watch ID, old/new state, time, actor), so later observation eligibility can be audited.

Add `watch_observations`: id, watch_id, membership_id, monitor_id, document_version_id, scope_version, watch_scope_revision_id, admitted_at, discovered_at, acquisition_event_id nullable, discovery_id nullable, fidelity, provenance_status, relevance_id nullable. Unique(membership_id, document_version_id, scope_version, watch_scope_revision_id). Focus-only revisions may change admission explanation without creating a new semantic processing identity. It records that this version entered this Research under this approval, including irrelevant material. References are validated together in the admission transaction. Only a relevant decision makes it eligible for ordinary evidence retrieval. A separate join from check source item to observation records repeated observation of the same version; do not duplicate semantic processing to show it in another check.

Processing identity is `(document_version_id, monitor_id, scope_version)`, already the relevance identity. A reattached membership may reference a previously completed relevance result at that same identity while retaining its new admission path. A new scope version gets new processing. Existing analysis hashes already include relevance and scope, so retain them. Do not globally reuse semantic analysis that used another Research's scope/prompt.

Cross-domain authority needs an explicit additional proof. Today both processing enqueue/handler and `provenance.py:validate_analysis_provenance` require Monitor.target_id = Document.source_id. For new observations, validate instead the full path: Monitor owns the approved membership Source/endpoint → bounded feed acquisition/discovery → linked publication acquisition result → exact DocumentVersion. Direct-page observations retain direct Source ownership. Add nullable observation reference to contextual jobs and ArticleAnalysis provenance so the verifier can reconstruct this path after detach. Do not remove the equality check globally or accept an arbitrary observation ID from a caller. Legacy analyses retain their existing verification branch and hashes. New cross-domain analyses require the new path and all its foreign-key/URL/policy/scope checks; missing or mismatched discovery edges fail closed. Reused analyses keep their original admission proof.

Admission is explicit, not “all Researches that happen to share Source.” Only eligible source-check subscribers acquire an observation. A cached unchanged version still creates any missing observation/processing obligation. Paused Research B receives no new observations merely because A fetched the Source. When B resumes and observes the same current version, it gets its own missing processing. Do not backfill all publication history on attachment.

Pause/detach prevents new external/paid operation admission. Already admitted observations may finish locally and retain their historical membership even if attachment closes meanwhile. Before each later external or paid operation, recheck current authorization, budget and subscription; cancel/suppress if no eligible subscriber remains. An HTTP response already in flight can be persisted, but cannot create a new Research observation for a subscriber withdrawn before observation admission. Record this as skipped, not acquisition failure. Previously admitted observations are never erased.

Legacy backfill is conservative: infer Watch ownership only from unambiguous Monitor need + current Watch target or known candidate/attachment evidence, preserving the source of inference. Already persisted per-Monitor relevance is admissible historical context with `legacy_relevance` provenance only when retained evidence unambiguously proves the Watch binding, including target corrections; current target equality alone is insufficient. When exact attachment dates are unknown, use a historical membership record with unknown dates, not invented timestamps. Unresolvable material stays in the advanced global library, not silently copied into every Research. List unresolved counts for review. Backfill performs no network calls, paid analysis or historical Claim/report rewrites.

## C. Processing correction without replacing the queue

Retain `document_version_process` jobs, handlers, retry factories and completion hooks. Add nullable `jobs.processing_monitor_id` and `processing_scope_version` as canonical context fields for new contextual jobs (do not repurpose jobs.monitor_id, currently used for Monitor-check authority). Resolve/validate payload equality and ownership before enqueue. Change idempotency keys to include context; change **all** active guards, rerun factories, direct API validation, integrity checks and recovery from version-only to the same identity. SQLite partial unique active index for contextual processing prevents bypass under concurrent writers. Acquisition-only legacy processing retains its separate version-only identity and cannot suppress contextual jobs.

After the M0.3 producer cutover, insert observation and processing obligation atomically (M0.2 intentionally persists pending admission for reconciliation); insert a completed-result reference instead if the exact contextual identity already succeeded. Workers persist relevance at its existing UNIQUE tuple and analysis/promotion at existing immutable identities. Jobs may have multiple observation/check subscribers; completion is one result fanned out through durable joins. A crash after result persistence and before job completion reuses the result on retry. Differing contexts may intentionally produce distinct analyses/Claims; that is not duplicate retry evidence and must not be misreported as independent corroboration.

Classify promotion outcomes explicitly. A well-formed completed analysis with no usable candidates or only rejected non-matching proposal excerpts can finish as no_accepted_evidence while retaining rejection reasons. Corrupt artifact hashes, forged provenance, ownership mismatch, invalid schemas and storage errors remain technical failures. The current all-unverified DomainValidation branch must not be caught indiscriminately and turned into success. Exact matching and support checks stay unchanged; only orchestration result classification changes.

Migration maps existing processing payload context into nullable columns when valid, preserving job IDs, keys and results. Do not rewrite historical identities. Drain old workers before new writers; old version-only guards cannot run alongside contextual producers. Add bounded reconciliation that finds observations lacking a job/result and creates only the missing obligation under the same transaction/identity. It is recovery in the existing queue, not another scheduler.

## D. Source, endpoint and publication identity

Preserve Source as publisher/origin, Document as canonical publication, DocumentVersion as immutable representation. Add small `source_endpoints` relation: id, source_id, normalized_url, endpoint_kind (rss/atom/page), active, discovered_from, verified_at, verification_outcome. Unique(source_id, normalized_url, endpoint_kind), preserving legacy Sources that share a URL. Cross-Source URL conflicts are explicitly unresolved and never automatically merged. Acquisition may share a URL/policy/representation result while publisher ownership remains separately validated. Add verified redirect aliases in this relation (alias_of_endpoint_id nullable); an alternate feed is a distinct endpoint until equivalence is proved, not automatically an alias. One selected monitoring endpoint per current membership in MVP; no independently scheduled feeds inside a Source. Existing homepage_url/feed_url become compatibility projections updated by the same Source service, not an alternate write authority. Advanced legacy endpoint edits update the relation through that service.

Source dedup uses exact normalized endpoints/known aliases and inspected identity, not name slug or whole-domain equality. Two publications on one host may be different Sources; hosted feed domains do not prove publisher ownership. Same-name/different-URL candidates must not silently resolve to the same Source. Preserve existing normalization for legacy Document keys; do not mass-renormalize URLs or merge stored Documents in migration. New aliases preserve the verified requested→final redirect relation. Untrusted canonical tags are hints, not authority to fetch/merge arbitrary pages. Case-sensitive path/query distinctions remain intact.

The legacy Source URL columns project a Source's default endpoints, not every membership's endpoint selection. A Research can select an existing validated endpoint without changing another Research's selection. Discovery of previously unknown redirect aliases may require one request per unknown alias before equivalence is known; after safe resolution, persistence and downstream processing must converge. Do not promise impossible pre-request dedup across unrelated unknown URLs, and do not weaken redirect safety to achieve it.

Source inspection is a bounded **preview** using existing AcquisitionPolicy/transport/parser, separated from AcquisitionService persistence of evidence. Persist only inspection metadata/short profile basis; no Document/evidence creation during preview. Inspect HTTP(S), DNS/peer/redirect safety, byte/time bounds, RSS/Atom signature, HTML alternate feeds and basic title/site metadata. Sitemap hints may be shown; MVP does not recursively crawl them. Present multiple feeds for selection rather than guessing. XML DTD/entities and unsafe URL schemes fail closed. Revalidate at every later fetch; “verified” is timestamped, not permanent permission.

## E. Feeds as sensors and shared acquisition

Add `publication_discoveries`: id, endpoint_id, acquisition_event_id, feed_item_key, feed_content_hash, feed_artifact_id, publication_url, discovered_at, content_fidelity (summary/full_feed_content), canonical_document_id nullable. Unique(endpoint_id,item_key,content_hash). Preserve item GUID, feed title/publication time and exact normalized content basis; feed HTML is sanitized using existing bounded extraction. Repeated links share article work but retain all discovery edges. Store returned article version via a result link, not by changing the feed artifact.

Use existing JobService for a thin `source_acquire`/`article_acquire` coordination handler, both calling **the same AcquisitionService**. New job kinds are durable continuations, not new transports, workers, schedulers or fetch implementations. Acquisition work identity includes canonical endpoint/publication URL, selected representation, and compatible fetch policy. Add canonical acquisition-key column/active uniqueness to jobs; subscribers join through `check_work`. A later request can reuse a completed acquisition only if it satisfies that request's freshness cutoff; otherwise schedule a new conditional fetch. A new explicit Check now requires an observation at or after its request time, except a compatible already-active check to which it coalesces. Cache age never substitutes for a missing per-Research observation.

Monitor-check orchestration subscribes to shared fetch work, releases its worker lease while waiting, and resumes/finalizes from durable child results; it must not busy-wait inside the sole worker. Existing `monitor_check` job remains the per-Monitor cadence authority. If introducing a waiting state would spread broadly, finish the orchestration job after dispatch and let check-work terminal projection finalize the source item; do not claim check completion from monitor job completion alone. Implement the latter smaller approach: Monitor activity/cadence success is recorded once when the acquisition result is consumed, keyed by source-item identity. The source-item active guard covers the interval after dispatch job completion.

One shared acquisition charge goes to the recorded initiating eligible request; other subscribers record reused acquisition. Each Research separately admits/budgets its own analysis. Policy compatibility (allowed channels, URL restrictions, freshness) is checked per subscriber. No paid scope is silently inherited from another Research. For zero-paid HTTP work, bounds still apply to requests, bytes, items, runtime and queue size. Suggested initial ceilings: 25 feed items/check, 10 linked articles/Research check, 2 MB/response, 3 redirects, 10 s/request, 120 s acquisition budget; defer surplus with explicit counts/cursor. Enforce service ceilings independent of editable policy.

Feed approval authorizes bounded retrieval of directly linked **public publications**, including cross-domain links, and says so in review. It does not approve monitoring the linked publisher or recursive links. Record discovering feed Source separately from article publisher. Reuse a known canonical Document regardless of which Source discovered it; do not skip it solely because source_id differs. For a new cross-domain origin, create a minimal unknown Source identity after safe inspection, without a Monitor or authoritative AI classification. Preserve existing source_id attribution on old Documents; record additional observed origin facts rather than rewrite history.

Fetch article first where possible. New feed observations are not automatically new article DocumentVersions. If retrieval fails, useful summary/full-feed content can become an explicitly feed-derived version with a discovery reference. Add representation/fidelity metadata to DocumentVersion (legacy unknown remains unknown), and compare unchanged hashes within the same representation. A feed summary must never overwrite the current article comparison base; consumers prefer retrieved article representation while citations remain version-specific. Later full retrieval can supersede presentation priority, not mutate feed evidence. Full-content feeds preserve that fidelity without pretending the linked article was fetched.

No access-control/paywall bypass, authenticated scraping, republishing, or indefinite raw response cache. Preserve the existing private normalized artifact storage needed for exact evidence; inspection/search caches are bounded separately. Site restrictions or unavailable formats produce honest unavailable/fallback states. PDF/JS extraction is not promised merely because a URL is valid; unsupported formats stay explicit. Existing supported content mechanisms remain available.

## F. Research read boundary

Add one small `ResearchEvidenceService` in proposed `newsroom/research_context.py`, used by Ask, Updates, Briefing and explanation reads. Input Watch ID + optional knowledge-time boundary; output eligible observation/version/evidence/claim IDs and provenance, bounded/paginated. This is a relational projection, not a new knowledge store.

Start from durable observations with relevant=true. Join exact versions to evidence, then ClaimEvidence; qualify each Claim using in-bound support and existing acceptance/state rules. Global acceptance alone cannot make a Claim publishable when its required support is outside the Research. Contradictions/context outside the boundary are not smuggled in through a global Claim packet. Show an in-bound qualification or omit the Claim; do not reinterpret global Claim truth. Shared Claim IDs may be referenced only with in-bound evidence. Never widen to all versions of a Document, all evidence of a Claim, all Claims of a Story, or all reports of a Topic.

Apply the boundary after every retrieval expansion and at final packet/citation construction, including snippets, question notes, corrections, comparisons and fallback answers. Scope Questions through explicit ownership/links and eligible evidence; an unrelated question linked to the same global Story is not automatically in scope. Historical retained observations remain eligible after detach; scope change does not remove them. Explain “collected under earlier scope” where relevant.

Add `watch` Ask scope to Python/API/DB CHECK and frontend types. Keep old object scopes advanced-only; no temporary Topic bridge. Current UI uses deterministic Ask; richer semantic Ask is not required for this rework. Expose this honestly rather than imply connecting Article Analysis changes Ask. Scoped Update text must be composed from eligible statements, not copied from potentially mixed global Story summary. Exact outside-context evidence is still accessible through explicitly labeled advanced navigation, never silently embedded in a Research answer.

## H. This check: reuse Runs with missing causal joins

Existing scheduler Runs span unrelated Monitors and jobs have one run_id; downstream processing is detached from that Run. Recent timestamps cannot reconstruct the exact expected set. Extend `runs` with nullable watch_id, request_key, scope_revision_id, requested_at, acquisition_closed_at and terminal outcome. Use existing run status vocabulary; typed outcome/phase lives in explicit columns or the existing validated summary JSON. A Watch Run is the Research check. Legacy/global Runs remain valid.

Add `check_sources`: id, run_id nullable during M0.5 compatibility dispatch, request_identity, membership_id, monitor_id, endpoint_id, pinned_scope_version, expected_at, terminal_status, outcome/reason, completed_at. Unique(request_identity,membership_id), plus unique(run_id,membership_id) for assigned Runs. M0.5 uses the existing Monitor dispatch job ID as request_identity; M1 uses the Watch request ID and requires run_id for Watch checks. Unassigned legacy-compatible source items cannot finalize a Watch Run. Snapshot all eligible sources for Start/Check now; periodic checks snapshot only sources due in that scheduler tick and label coverage accordingly. Add `check_work` links (source_item_id, job_id or observation_id with checked discriminator, stage, outcome_reference), unique per linked work. Shared jobs can serve multiple Runs. The legacy jobs.run_id is not overwritten to represent later subscribers.

`POST /watches/{id}/checks` accepts request_id UUID, reason start/manual, expected_scope_revision; response check_id, existing/coalesced, phase, counts, next_due_at. `POST .../resume` activates existing membership Monitors and makes them due now; first Start uses the same transactional request service. Replaying a UUID with different inputs returns conflict. Same concurrent manual requests coalesce with the active equivalent Watch check; no second active manual check. Automatic subset checks may be joined/expanded only before their expected set is sealed; otherwise manual intent is durably queued as the next bounded check. No silent dropping of unrepresented sources.

Start transaction validates positive approved scope, at least one usable approved endpoint and cost policy; creates pending Run/source items, enables Monitors and sets due_at=now. Scheduler consumes these items through ordinary Monitor jobs. No synchronous fetch in the API and no independent timer loop. Status says “Due now; waiting for scheduler” if runtime is stopped; do not promise zero wall-clock latency. New ticks coalesce both active jobs **and active source items**, not only queued/running monitor_check rows.

Terminal outcomes: updates_found, no_source_change, new_material_irrelevant, no_accepted_evidence, partial_failure, failed, cancelled. checking/processing/preparing/retrying are nonterminal phases. Partial failure retains successes and identifies failed sources; deferred/retry includes a persisted deadline. All required descendants (including bounded report refresh) must finish or reach explicit terminal failure/cancellation before the check closes. An exhausted synthesis job is terminal with a stale Briefing warning, never infinite preparing. Surplus work beyond bounds is deferred explicitly and not falsely counted as attempted. Completion counters use distinct persisted IDs and exclude cached historical successes except explicitly reused work in this check.

Outcome precedence: pending descendants first; then explicit cancellation; technical failures yield partial_failure if any work succeeded, otherwise failed; then new scoped Updates; then completed relevant processing without accepted output; then new irrelevant material; finally no_source_change. An unchanged global article newly learned by Research B can therefore yield updates_found. Keep acquisition outcome and synthesis outcome as separate fields so a failed refresh does not erase successful acquisition. All list/fanout limits paginate or persist continuations; no global latest-100 query or silent source cutoff is allowed. A request exceeding the supported per-check source ceiling must show the bound or durably split into named batches before acceptance.

## J. Necessity, alternatives and adversarial results

| Change | Why existing architecture is insufficient; rejected alternative | Failure/reversal/future check |
|---|---|---|
| Watch scope/history metadata | Target descriptions alone cannot preserve original prose, Focus revisions or complete approval history; new Research root duplicates lifecycle | Atomic snapshots; no historical rewrite; additive migration/backfill |
| Membership intervals + observations | Deleted joins and version-only processing cannot prove admission; source-ID filtering leaks | Closed interval retains old observations; unknown legacy membership flagged; no purge |
| Contextual job identity | Changing only idempotency text leaves version-only active guard blocking B | All enqueue/rerun/recovery paths updated together; old jobs retained; isolated upgrade rehearsal |
| Endpoints + discoveries | Slug identity and singular Document.source_id lose feed/origin path; duplicate publisher Documents violate canonical identity | Alias conflicts reviewed; redirects safe at each hop; preserve immutable representations |
| Shared acquisition continuation | Per-Monitor acquisition duplicates simultaneous requests; a process mutex loses crash state | Existing queue/transport and durable subscriptions; freshness explicit; no separate scheduler |
| Watch-scoped read projection | Broad Story/Document expansion leaks even after initial filtering | Adversarial packet/citation tests; reject raw global prose; exact versions retained |
| Watch LivingReport target + scoped delivery key | Existing report targets and digest uniqueness cannot represent Research-isolated current/delivered intelligence | Preserve legacy artifacts, qualify new inputs, extend existing report model only |
| Run/source/work joins | Latest-job heuristics cannot answer this-check completeness | Expected set pinned; child completion/recovery; old errors excluded |
| Layered profile assertions | Existing operational profile overwrites counters, not reviewed intellectual assessments | User edits append; role never updates Claim state |
| Setup capability authorization | Current routes require saved Watch/budget and lack external search/intent contracts | One-off admission, no hidden enabling/spend; keep manual/basic lane |

Final challenge modifications: move evidence isolation before workspace outputs; explicitly cover unchanged observations and active guards beyond idempotency keys; reuse Runs rather than invent a parallel check engine; add representation-specific unchanged comparison for feeds; distinguish current report from delivery scope; prevent source detach from erasing admission history; retain old artifacts as legacy rather than falsely certifying isolation. Future Time Machine relies on both publication time and admitted/accepted/revision times. Full historical query UI is deferred.


## K. Final M0 audit: binding refinements (D20–D26)

These refinements supersede weaker earlier assumptions; M0.1–M0.6 in EXECUTION_PLAN own delivery.

**Scope writes.** Extend the existing transactional helpers, with proposed `research_membership.py` owning membership/revision writes, not network work. All term, Question, Subject, Watch overlay and Story correction callers must participate in the same transaction. `_refresh_need_scopes_tx` must preserve each Watch's approved overlays; `_write_scope_history` may reuse an identical semantic version. Record target binding independently of semantic terms. Reattach refreshes a reused Monitor to current approved scope before enabling admission. Queued jobs retain old immutable scope and target provenance. Topic/Question are normal Research; Subject/Story stay compatible advanced modes. Source-target acquisition-only Watches have no semantic need: return explicit unavailable contextual eligibility until a valid existing scope exists, never invent matching terms or clone the target.

**Unchanged feeds.** Introduce an immutable successful endpoint snapshot and its item→exact-version associations in M0.2; acquisition events alone cannot express this today. A feed 304 references its last successful snapshot, not all Source Documents. An unknown/absent snapshot requires bounded unconditional recovery or explicit unavailable outcome. Direct-page 304 with missing prior version follows the same rule. A 200 same-hash result still admits missing observations. Snapshot identity is acquisition event plus endpoint/representation; item identity preserves GUID/id when supplied and a documented deterministic fallback when absent. Preserve full-content versus summary basis for new items; legacy truncated summaries remain unknown. Acquisition persistence and snapshot/result association commit atomically; crashes cannot publish an apparently complete manifest. Minimal snapshots do not authorize linked-article fetching before M1.

**Observation versus execution.** M0.2 writes pending obligations without launching new contextual jobs; M0.3 reconciles them. `research_observations.py` owns admission and durable result links. Jobs may serve multiple admissions at the existing (version, Monitor, semantic scope) identity. Do not use a single mutable observation pointer as the whole subscriber set. A completed relevance decision is not proof that analysis/promotion descendants finished: reuse each valid completed stage and reconcile missing descendants. Retry admission is distinct from reusing a successful result. Fence completion and side effects to current lease owner/attempt inside the same transaction; a stale worker cannot publish or finalize after a newer lease. Paid invocations retain existing reservation/ambiguous-outcome protections.

**Canonical material.** Artifacts, Documents, versions, global Stories, Claims and Evidence retain their existing identities. Current automatic Claim/span identities include analysis/candidate provenance; distinct contextual analyses can legitimately create separate objects. Never deduplicate those rows merely by equal text, and never clone them merely to attach a Watch. Projection/counting must avoid presenting equivalent representations as independent corroboration. Global acceptance remains global; scoped support determines use, not a second per-Watch truth mutation. Story resolution uses pinned context for historical explanation; mutable Monitor need must not rewrite analysis ownership. Promotion→Story→report→alert job identities remain stable and carry causal/context links.

**Runs.** Proposed `research_checks.py` coordinates only existing queue subscriptions and completion. `check_work` needs typed links with actual FKs (job/observation/result), exactly one referenced kind per row, unique (source_item, kind, referenced_id), and durable parent-child dependencies. Expected sources and each parent's descendant set are sealed explicitly. Child creation plus dependency insertion plus parent sealing is atomic. Only a sealed, terminal dependency closure can close a Research Run. JobService's current `_maybe_finish_run_tx`, manual finish, cancellation, budget failure and lease exhaustion must delegate Watch Runs to this authority; keep legacy unscoped behavior. Finishing dispatch alone is insufficient. No circular report-refresh dependency is permitted.

**Consumer boundary.** Current source health, scheduling, setup counts, policy editing, proposals and coverage continue reading current attachments. Historical evidence/history/export read intervals and observations. Question task planning's current Watch context remains operational; it is not a substitute for Ask eligibility. Ask must gate retrieval, task/gap expansion, corrections, snippets and final citation serialization. Reports must gate `_story_ids`, `_accepted_claims`, `_collect_sections` and `_claim_evidence`. Temporal Watch attribution currently omits Questions: add explicit qualified Watch associations, including Question Watches. One global Story event may carry multiple Research labels; count it once in Home, and use stable (Watch,event) identity for per-Research acknowledgement. Never copy global alert bodies or Story summaries into scoped Home/Updates. Saved/history/global FTS remain clearly advanced until explicitly scoped; selecting a Research cannot silently relabel them.

**Recovery contract.** Safe logical export remains a bounded metadata interchange, not full disaster recovery. Existing omissions include normalized artifacts, relevance and executable job payloads; do not broaden private-content export implicitly. New lineage metadata exports retain original IDs with explicit completeness/unresolved-reference metadata, taken from one read snapshot. A new partial archive is validated as an archive, not certified as runtime evidence. Reject unsupported incomplete runtime imports before mutation; preserve supported legacy import behavior and report limitations. Never fabricate omitted evidence or restart paid jobs. Duplicate/conflicting rows must yield accurate inserted/skipped/conflict counts; authority conflicts fail atomically, not silently `INSERT OR IGNORE`. Full reconstructable evidence and resumable obligations are proved through the existing verified SQLite backup/restore path with matching code and required artifacts. Every slice tests both contracts; M0.6 integrates them. Retained evidence/revisions restrict deletion of causal history. Current retention removes backups/sessions, not a licence to add history purge.

### Concept lifecycle review

Each row answers necessity/existing equivalent, state/identity, owner, immutable/mutable/history, uniqueness, and retry/detach/scope/restore behavior. All restore paths follow the recovery contract above.

| Concept | Necessity, existing equivalent, state and stable identity | Owner; immutable / mutable / retained history | Uniqueness; retry; detach; scope; restore |
