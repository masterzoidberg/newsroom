# Newsroom Complete

Newsroom is a private personal intelligence workspace for someone who repeatedly follows a niche subject, person, organization, developing event or research question. It reduces repeated searching and helps the user understand what changed, what matters, what supports a claim, and what remains unknown.

The core workflow is: install → Start Newsroom → create a private workspace → describe an interest → review terminology and Sources → choose cadence → start a Watch → receive useful changes → inspect summary → Claim → exact Evidence → source/version → maintain an evolving report and unanswered questions.

## Product contract

- Watch is the user-facing monitoring objective. Topic is a subject area; Subject is a named person/organization/entity; Story is a developing event; Source is a publisher/feed/page; Research Question is an unresolved information need; Evidence Gap is a canonical missing-evidence record. Monitor is the internal Source collection schedule. Do not rename stored domain types or introduce competing objective types.
- Default to local, approximately zero incremental provider cost. Label local heuristic analysis honestly. Semantic assistance may use a deliberately configured capability; its suggestions are editable proposals, never approved scope or trusted Evidence automatically.
- Users approve discovered Sources with rationale, provenance and limitations before collection. Manual URL/feed and existing-source selection always work. A recommendation is not a source credibility verdict; verified text is not proof of truth.
- Collection is scheduled while the supported Windows user/session is running. Browser closure is compatible with background collection once qualified. Sleep/power-off/pre-login limitations are explicit, with safe bounded catch-up; no near-real-time promise unsupported by the selected source/channel.
- Living reports change with accepted evidence, preserving revisions and corrections. Briefings summarize a user-chosen period/cadence. Alerts prioritize material causes with understandable reasons and an accessible lower-priority history.
- Search, saved/history and Watch context are usable by names. Summaries retain traceable Claims, evidence quality and disagreements; hypotheses remain distinguishable from accepted Claims. No evidence means a truthful wait/refusal, not generated filler.
- Status gives an honest collecting/processing/waiting/needs-attention outcome. Recovery explains what is known about stored data and gives a safe next step; it never guarantees data safety when integrity is unknown.

## Principles

Outcome-first language, progressive disclosure, explicit AI/cost choices, low cognitive load, accessible responsive controls, and actionable empty/loading/error states. Keep the current React/FastAPI/SQLite architecture and dark design language. Evidence quality and understandable uncertainty outrank output volume.

## Must-have completion gates

All 30 capabilities in FEATURE_GAP_ANALYSIS have a user-verifiable acceptance path. The six journeys in JOURNEY_VALIDATION pass against a named isolated release artifact. Ordinary setup needs no raw IDs, shell commands or knowledge of API/worker/scheduler roles. Manual/local monitoring remains useful without a paid account. Assisted vocabulary and source recommendations have measured bounded output quality and truthful unavailable/manual fallbacks. Installed start/background/recovery/upgrade and supported phone/PWA behavior are qualified. Human real-use value is supported by the unchanged evaluation protocol; engineering tests alone cannot confer that verdict. Installation/use/recovery/maintenance documentation is current.

## Explicit non-goals

No multi-user SaaS, cloud corpus, billing platform, social network, general web chat, unlimited crawling, inferred truth scores, broad paid autonomous operation, source access bypass, redesign of the evidence ledger, or recreation of removed Coverage/Blind Spot/fragility projections. No requirement for all providers/platforms, offline article reading, OS push while closed, pre-login monitoring, or a new desktop framework. Commercial expansion and paid Ask require their existing value gates.

Completion is a qualified product experience, not the existence of every API or a fixed test count. An engineering candidate can precede real-use acceptance; it must be labeled accordingly.
